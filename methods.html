How We Built the Field Guide

This page explains how each entry was found, researched, labeled, and written. The short version comes first. Technical details follow in expandable sections.

The short version

  1. We searched open board lists, maker catalogs, and hardware news for open-source gear.
  2. An AI research agent studied each item. It read official pages, datasheets, design files, and store listings. It saved every fact with a source.
  3. Python scripts checked each research file. Missing facts, bad links, and odd prices were flagged and fixed.
  4. Rules turned the facts into labels and scores.
  5. AI agents rated ease of use with a fixed rubric.
  6. AI agents wrote each page in plain words from the research file only.
  7. A style checker and a person reviewed the pages.

How the scores work

Openness

LevelThe rule
Wild OpenFull board design files under an open license, plus fully open coding tools
Open BoardBoard design files or schematics are public, and the main tools are open or mostly open
Open CodeThe coding tools and software are open, but the board design is private

Gear that meets none of these rules stays out of the guide.

Capacity

Capacity runs from 0 to 100. It answers one question. How much work can this board juggle at once? The score blends six parts.

PartWeightWhat it measures
Compute25%Processor cores times speed, on a log scale
Memory25%Working memory, on a log scale
Storage10%Space for programs and files, on a log scale
Pins15%Input and output pins, up to 40
Radios10%Built-in radios, up to 3
AI chip15%AI speed in TOPS, on a log scale

Log scales keep giant boards from crowding out small ones. A board twice as fast does not get twice the score. Some entries lack a spec. Those entries say their score may run low.

Value for money

Value divides capacity by the square root of the lowest price we found. The square root keeps costly boards in the running. The result becomes a meter from 1 to 5. A cheap, capable microcontroller often scores high. A powerful AI board can score well too.

Affordability and starter cost

The price band uses the lowest US price we found. The starter cost adds a typical cable, power supply, and a few first parts.

Easy to buy in the US

LabelThe rule
Easy to findThree or more US stores showed it in stock
A few storesOne or two US stores list it
Import onlyOnly stores outside the US list it

Rubric scores

AI agents scored ease of use, code needed, effort, docs quality, and community size. Each score follows written anchors. The guide marks these scores with an asterisk. Each one shows a short reason on its page. "Newcomer friendly" requires an ease score of 4 or 5, beginner-level code or less, and decent docs.

Build ideas

Each entry lists 10 to 20 build ideas. Every idea names the abilities it needs. A script rejects any idea that needs an ability the board lacks. A board with no camera port gets no camera ideas.

Prices

Agents copied prices from store pages on the date shown. Some stores block automated visits. Those stores may be missing. Prices are estimates and can change at any time. Price and availability vary by vendor. We do not refresh prices on a schedule.

Technical details: pipeline and files

Pipeline

The project runs as Python 3 scripts with YAML and CSV files. No paid AI service is called from code. Research and writing agents ran inside Claude Code.

Checks

  • Every dossier needs three or more distinct sources.
  • Every price needs a store link and a checked date.
  • Numbers must be numbers. Labels must come from fixed lists.
  • Every idea's needs must match the board's abilities.
  • Every page passes the style checker.
  • Links to known bad domains are removed.
Technical details: agreement checks

Rubric scores will be double-coded on a sample of entries. A second agent scores the same entries blind. Weighted kappa measures agreement. Fields below 0.7 get revised anchors and a rescore. Results will appear here once the full catalog is scored.
